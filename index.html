Give an agent a real program to play with, hide the code, and ask it to rebuild the whole thing. Even top agents struggle with it.

ProgramLab gives agents 1,261 such programs to practice on. Environments are available here.

Train one agent, or a whole team

Using Qwen3.6-35B-A3B, we run RL on ProgramLab and evaluate on ProgramBench:

  • Single agent: 13.7% → 24.0% in Claude Code under a two-hour budget.
  • A five-agent team: 17.2% → 25.0% in Agensh under a 30-minute budget.

Gains transfer across harnesses. We train only in GitHub Copilot CLI, and the policy improves on ProgramBench in every harness we test, including three it never saw in training: Claude Code (+10.3), Codex CLI (+8.3), and mini-SWE-agent (+4.1). Under an extended six-hour budget, Claude Code goes from 19.0 to 27.6.

The agent learns to write programs that compile. Each RL step runs 1,024 rollouts (64 tasks × 16), each with a two-hour, 128K-context budget. Over training, rollouts grow from about 43 to 72 turns, mean reward rises, and the share of rollouts ending with a compiling program grows 8×, from 3.4% to 27.9%.

Multi-agent RL also works. RL on ProgramLab raises a five-agent Qwen3.6-35B-A3B team from 17.2% to 25.0% (+7.9 points) on ProgramBench under a 30-minute budget.

Data recipe

The task. We follow the setting of ProgramBench (Yang et al., 2026). The agent works in a cleanroom container with a build toolchain and no network. It can run the reference executable and read its documentation, but not the source. It writes a program in any language, plus a compile.sh that builds it.

What's in ProgramLab? ProgramLab contains 1,261 tasks from 1,261 distinct public repositories (566 Go, 415 Rust, 280 C/C++), with 187,073 hidden behavioral tests in total. The median project has about 11.5K lines of source code, and about 150 exceed 100K lines. Each task contains:

  • A reference executable, built from a pinned commit and shipped execute-only.
  • Documentation: usage text, help output, man pages, and any fixtures the agent cannot create itself.
  • A hidden test suite: a median of 127 tests that run the agent's program and compare its observable behavior with the reference.
    • These cover 76.6% of the reference's first-party lines (over 90% for projects under 5K lines), with far fewer tests than ProgramBench's 770.

Tasks ship in the ProgramBench format, so the official ProgramBench evaluator scores them without modification. Following ProgramBench's difficulty score, 205 tasks are easy, 888 medium, and 168 hard.

    assert "The certificate is at \"./example.org.pem\" and the key at \"./example.org-key.pem\"" in proc.stderr

    assert key_file.is_file()

Why ProgramLab is suitable for RL

  • Tests you can trust. A test is kept only if it passes on the real program, passes every time, and fails on a do-nothing binary. Tests that fail on the reference in the cleanroom (4,047), pass on a no-op binary (1,735), or are flaky (550) are excluded from scoring.
  • Hard to cheat. We keep ProgramBench's cleanroom: the agent can run the program but not read it, and scoring rebuilds the agent's program in a fresh container and runs tests it has never seen. Since every task comes from a new repository, we also scrub each image for leaks: source files, build caches, dependency sources, git history, and docs that describe internals. Before release, we check that only the execute-only binary remains, with no readable copy and no network. This matters more for RL than for evaluation, since a policy trained on tens of thousands of rollouts will exploit any loophole it finds.
  • Cheap to score. Coverage-guided generation keeps suites small: a median of 127 tests (ProgramBench uses 770) still covers 76.6% of the reference's code, so scoring thousands of rollouts per training step stays fast.
  • Tasks at the right difficulty. Tasks range from small tools to projects with over 100K lines of code: 205 easy, 888 medium, and 168 hard. This makes it easier to pick tasks that suit your agent: hard enough to learn from, but not out of reach. The spread also makes curricula simple: our multi-agent run trained 50 steps on easy tasks, then 50 on medium.

How we build ProgramLab. We collect open-source projects from package registries (Homebrew, crates.io, pkg.go.dev) and GitHub, and keep those that reliably build a standalone executable. For each task, Codex CLI with GPT-5.5 builds the environment in the three steps below, and a separate validator re-checks each step:

  1. Build the reference. Compile the project's main executable and record the build script.
  2. Synthesize behavioral tests. Probe the executable and write tests that assert on its observable effects. A test is kept only if it passes on the reference, passes on repeated runs, and fails on a dummy binary that accepts any input.
    Coverage-guided iteration. After each round, we measure line coverage of the reference on an instrumented build and feed the coverage report back to the agent, which then writes tests for code that is not yet covered. The loop stops when coverage stops improving.
  3. Package the cleanroom. Ship an execute-only binary and its documentation; remove source, build caches, and version-control history.

Agentic RL in ProgramLab

For scoring, the agent's program is rebuilt in a fresh container and run against the hidden test suite. The reward is the fraction of tests passed, r = |Tpass| / |T| ∈ [0, 1].

Trajectory collection for black-box harnesses. We run off-the-shelf harnesses as the policy's interface.

  • Logging every model call. Each harness reaches the model through a local proxy, the only network route the cleanroom allows. The proxy logs prompt tokens, sampled tokens, and log-probabilities for every call from every agent. Calls are merged into training sequences by prefix matching, and only model responses are trained.
  • Context compaction. When the harness summarizes its history, a new training segment starts. The summarization call is trained too.
  • Asynchronous training. Generation and training overlap, with a cap on how stale samples can be.

Multi-agent training. We train Qwen3.6-35B-A3B in an experimental version of the Agensh harness with five agents: one leader writes test cases and hands implementation work to four workers. Each rollout runs in its own Docker environment, where agents share code through Gitea, talk on Mattermost, and share notes through a common context. All five agents use the same weights. We train 50 steps on easy tasks, then 50 on medium. Each rollout gets 30 minutes, after which we export the Gitea repository and score it with ProgramLab.
